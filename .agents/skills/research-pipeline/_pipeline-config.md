## Full Data Suite

Each robot session produces **six compressed Parquet files** — the TriLattice feature stream, per-stream bar logs, a pivot log, and a traditional time-bar baseline. See `docs/references/dataset-reference.md` for authoritative column definitions, schema details, and loading patterns.

When `NoiseFlipRate > 0`, the same six files are produced under `data/noise/noise_XXX/` (where XXX = flip rate × 100, zero-padded to 3 digits, e.g. `noise_010`, `noise_020`, `noise_030`). All schemas are identical to their baseline counterparts. See `docs/references/dataset-reference.md` for noise injection architecture, cTrader parameters, and noise-specific loading patterns.

### 1. TriLattice Features (30 columns)

Primary dataset. One row = one `CombinedFeatures` vector emitted at every confirmed Stream A pivot.

- **Path pattern**: `data/features_<symbol>_<yyyyMMdd_HHmmss>_<yyyyMMdd_HHmmss>.parquet`
- **Columns**: 30 (Pivot Metadata 10, Structure Labeling 4, Bar Features 6, Structure Features 5, Context Features 5)
- **Python access**: `pl.read_parquet(path)` or `pl.scan_parquet(path)`

**Key columns**: `ConfirmTime`, `Label`, `Regime`, `BarReturn`, `ValidationStatus`, `SequenceContext`, `ImbalanceFlag`. For the full 30-column schema with Arrow types, sources, and descriptions, see `docs/references/dataset-reference.md`.

### 2. Traditional Time Bars

Raw OHLC bars from the same cleansed tick stream, with a fixed clock interval derived from governance parameter `B` (bars per hour). Used as a traditional baseline in validation experiments.

- **Path pattern**: `data/traditional/timebars_<symbol>_<yyyyMMdd_HHmmss>_<yyyyMMdd_HHmmss>.parquet`
- **Schema**: `OpenTime`, `CloseTime`, `Open`, `High`, `Low`, `Close`, `TickCount`, `DurationSeconds`, `SumAbsDelta`

### 3. Stream A (Tick) Bars

Bars generated by `TickBarGenerator` with fixed tick count `N`.

- **Path pattern**: `data/bars_tick/bars_tick_<symbol>_<yyyyMMdd_HHmmss>.parquet`
- **Schema**: `OpenTime`, `CloseTime`, `Open`, `High`, `Low`, `Close`, `TickCount`, `DurationSeconds`, `SumAbsDelta`

### 4. Stream B (Activity) Bars

Bars generated by `ActivityBarGenerator` with adaptive threshold `θ₀`.

- **Path pattern**: `data/bars_activity/bars_activity_<symbol>_<yyyyMMdd_HHmmss>.parquet`
- **Schema**: `OpenTime`, `CloseTime`, `Open`, `High`, `Low`, `Close`, `TickCount`, `DurationSeconds`, `SumAbsDelta`

### 5. Stream C (Imbalance) Bars

Bars generated by `ImbalanceBarGenerator` with fixed threshold `θ_C`.

- **Path pattern**: `data/bars_imbalance/bars_imbalance_<symbol>_<yyyyMMdd_HHmmss>.parquet`
- **Schema**: `OpenTime`, `CloseTime`, `Open`, `High`, `Low`, `Close`, `TickCount`, `DurationSeconds`, `SumAbsDelta`

### 6. Confirmed Pivots

Swing pivots from both Stream A and Stream B, stored for cross-representation validation.

- **Path pattern**: `data/pivots/pivots_<symbol>_<yyyyMMdd_HHmmss>.parquet`
- **Schema**: `TimestampConfirm`, `TimestampPeak`, `PricePeak`, `PriceAtConfirm`, `Type`, `Trigger`, `Confidence`, `ThresholdUsed`, `EmStdAtConfirm`, `SourceStream`

### 7. Noise-Injected Datasets (EXP-002)

When `NoiseFlipRate > 0`, all six dataset types are produced under `data/noise/noise_XXX/` with identical schemas. The `TickDirectionNoiseInjector` sits between `TickCleanser` and bar generators, flipping tick-rule direction at configurable rates (10%, 20%, 30%) with adaptive Mid-price perturbation.

- **Path pattern**: `data/noise/noise_XXX/<same sub-structure as baseline>`
- **Noise levels**: `noise_010` (10%), `noise_020` (20%), `noise_030` (30%)
- **Schemas**: Identical to baseline counterparts (see items 1–6 above)
- **cTrader parameters**: `NoiseFlipRate`, `NoiseSeed`, `NoisePricePerturbation`
- **Loading**: See noise-specific loading pattern in `docs/references/dataset-reference.md`

### Data Loading

Standard loading pattern (use in all experiment code):

```python
import polars as pl
from pathlib import Path

DATA_DIR = Path("/Users/jerryinyang/cAlgo/Sources/Robots/TriLattice/TriLattice/data")
path = sorted(DATA_DIR.glob("features_*.parquet"))[-1]

# Polars reads ZSTD-compressed Parquet transparently
df = (
    pl.scan_parquet(path)
    .select(["ConfirmTime", "Label", "Regime", "BarReturn", "ValidationStatus"])
    .filter(pl.col("ValidationStatus") == "Valid")
    .sort("ConfirmTime")
    .collect()
)

df = df.drop_nulls().to_pandas()
# Apply holdout split — see OOS Holdout Rules below
```

**Important**: String enum columns (`PivotType`, `Trigger`, `Confidence`, `Label`, `Regime`, `ValidationStatus`) require explicit handling. Convert to numeric codes when needed.

### Enum Encoding Reference

| Enum | Values |
|------|--------|
| `PivotType` | `High=1`, `Low=−1` |
| `Trigger` | `Price=1`, `Time=0` |
| `Confidence` | `High=1`, `Low=0` |
| `Label` | `HH=4`, `HL=3`, `LH=2`, `LL=1`, `Ambiguous=0` |
| `Regime` / `ContextRegime` | `Low=0`, `Medium=1`, `High=2` |
| `ValidationStatus` | `Valid=2`, `Pending=1`, `Artifact=0` |

## OOS Holdout Rules

**These rules are non-negotiable and enforced by governance at every stage.**

TriLattice data is temporally ordered by `ConfirmTime`. The holdout split must respect chronological ordering.

### Nested Chronological Split

```
Full Dataset (ordered by ConfirmTime)
├── First 70% = ANALYSIS SET (used for all experiments)
│   ├── First 70% of analysis set = TRAIN SET
│   └── Last 30% of analysis set = TEST SET
└── Final 30% = GLOBAL HOLDOUT (never used)
```

### Rules

1. **Never load, inspect, or use the final 30%** of the dataset in any capacity.
2. All analysis, training, testing, and validation uses only the first 70%.
3. Within the analysis set, use a 70/30 chronological train/test split.
4. The holdout is a **global reserve** — it persists across all experiments.
5. Any experiment that touches the holdout set is a **governance violation**.
6. **Never use future data** — all analysis must respect the confirmation timestamp ordering.

### Code Pattern

```python
import polars as pl

# Load and sort chronologically
df = pl.scan_parquet(path).sort("ConfirmTime").collect().to_pandas()

# Chronological split (data is time-ordered by ConfirmTime)
analysis_cutoff = int(len(df) * 0.7)
analysis_set = df.iloc[:analysis_cutoff]
# holdout = df.iloc[analysis_cutoff:]  # DO NOT UNCOMMENT OR USE

# Within analysis set: train/test split
train_cutoff = int(len(analysis_set) * 0.7)
train_set = analysis_set.iloc[:train_cutoff]
test_set = analysis_set.iloc[train_cutoff:]
```

## Programme Principles

These binding constraints apply to all TriLattice research. All work must respect them.

| Principle | Description |
|-----------|-------------|
| **Simplicity over complexity** | Always choose the simplest, most robust approach that answers the question. Justify complexity before using it. |
| **No academic-finance pitfalls** | Reject techniques relying on assumptions known to fail in real markets (normality, stationarity, i.i.d., constant volatility). Prefer empirical/bootstrap/permutation methods. |
| **Data-driven** | Conclusions emerge from data, not assumptions. No pre-conceived shapes or distributions. |
| **Non-parametric by default** | Distribution-free methods first. Parametric only with non-parametric cross-validation. |
| **Adaptive** | All parameters derived from data, never hardcoded. No magic numbers. |
| **Non-conformational** | Never force data into predefined shapes or models. |
| **Human-in-the-loop** | All plans, designs, implementations, and conclusions require explicit approval (standard mode) or clear governance verdicts (executor mode). |
| **Single hypothesis per experiment** | Each experiment answers exactly one question. Scope creep is a governance violation. |
| **Complexity budget enforced** | Every experiment has defined limits on statistical tests, visualisations, and new code modules. |
| **Look-ahead bias prevention** | Labels are assigned at `ConfirmTime`, never at peak/trough timestamp. All analysis must respect this. |
| **Cross-validation integrity** | Only `ValidationStatus == "Valid"` pivots should be used for model training unless explicitly testing validation methodology. |

## Checkpoint System & Phase-Based Research

TriLattice research is organized into **phases**, each with a checkpoint in `docs/experiments-docs/checkpoints/`.

### Phase Lifecycle

1. **Design Phase**: Create `design.md` before any experiments begin
   - Define phase objectives and research questions
   - List planned experiments with rationale
   - Specify methodology and success criteria
   - Reference previous phase's `retrospective.md` if applicable

2. **Execution Phase**: Run experiments according to `design.md`
   - Each experiment follows the 8-stage pipeline
   - Update `python/experiments/INDEX.md` as experiments complete
   - Update `docs/experiments-docs/INDEX.md` with comprehensive findings

3. **Retrospective Phase**: Create `retrospective.md` after phase completes
   - Summarize outcomes vs. objectives
   - Document lessons learned
   - Propose next phase's research direction
   - Update comprehensive index with key findings

### Checkpoint Naming Convention

```
docs/experiments-docs/checkpoints/YYYY-MM-DD-###-descriptive-name/
```

- Date: When the phase design was finalized
- Number: Sequential phase number (001, 002, etc.)
- Name: Brief descriptive slug

## Governance Verdicts

All governance reviews produce one of three verdicts:

| Verdict | Meaning | Action |
|---------|---------|--------|
| **APPROVE** | All checks pass. Pipeline advances. | Proceed to next stage. |
| **REVISE** | Issues found. Specific changes required. | Route to failing skill with issues. Allow up to 2 revision cycles. |
| **REJECT** | Fundamental issues. Cannot proceed as-is. | Hard stop. Present rationale. Cannot be overridden. |

### REVISE Routing

When governance issues REVISE, the verdict identifies:
- `FAILING_ARTIFACT`: which file needs fixing (scope.md, analysis-plan.md, code, audit.md, results.md, report.md)
- `REQUIRED_SKILL`: which skill should fix it (experiment-quant-analyst, experiment-developer, experiment-auditor, experiment-documenter)

## Code Standards

- **Style**: PEP 8, max 100 char line length, f-strings, import grouping (stdlib → third-party → local)
- **Type hints**: Required on all public function parameters and return values
- **Docstrings**: Required with Parameters and Returns sections
- **Separation**: Analysis functions (pure computation) ≠ Plotting functions (figures) ≠ Experiment scripts (orchestration)
- **Data handling**: Polars preferred for performance with Parquet; pandas acceptable for tabular; numpy for numerical
- **NaN handling**: Explicit — never let NaN propagate silently
- **Function size**: Split if exceeding ~30 lines
- **Look-ahead bias**: Never use data from after `ConfirmTime` when analyzing a pivot event
