# EXP-100 Memory-Safe Apparatus Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task with review checkpoints.

**Goal:** Implement EXP-100 as a causal Nautilus `BacktestNode` apparatus whose peak memory is bounded by fixed batches and disk-backed live state, while emitting complete deterministic contract-v1 evidence.

**Architecture:** Each cell runs in its own process and owns one native streaming `BacktestNode`. The strategy aggregates 1-minute bars online, stores only bounded feature history in Python, and keeps unresolved levels, raids, and sparse TPO bins in a cell-local SQLite state store. Append-only Parquet/JSONL writers publish evidence without accumulating whole-run dataframes.

**Tech Stack:** Python 3.13+, NautilusTrader 1.230.0, PyArrow, Polars, SQLite, pytest, and the existing Xen emission/adjudication modules.

## Global Constraints

- Every price-primary decision runs inside Nautilus `BacktestNode`; no vectorized price-strategy backtest is permitted.
- One `BacktestNode` exists per process; multi-cell execution uses subprocesses and the default scheduler concurrency is one.
- Replay is TRAIN-only and uses the frozen EXP-100 scope, real catalog prices, causal confirmed-bar state, and no holdout contact.
- `BacktestRunConfig` uses a fixed positive `chunk_size` and `dispose_on_completion=False`; engine analysis is disabled and the venue account is frozen.
- No full-run `list[Bar]`, `to_dicts()`, `to_list()`, `read_bytes()`, or whole-run Polars/Pandas evidence frame is introduced.
- All output rows are written or the cell is explicitly marked incomplete; memory failure is never published as an empty result.
- Required emission-v1 files remain present, including empty fills/orders/positions tables, `event_log.jsonl`, `instrument_id_map.json`, and non-STUB fence attestation for a real run.
- `cost_model` is exactly `NO_COST_CHARGED`; no commission, spread, funding, swap, or local accounting path is added.
- Timestamps, strict raid/inclusive return semantics, ambiguity handling, confirmation chronology, TPO conservation, and deterministic future-destroy integrity remain exactly as approved.
- No golden trace is generated by the implementation.
